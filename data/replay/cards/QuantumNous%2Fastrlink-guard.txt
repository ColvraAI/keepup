# AstrLink Guard
AstrLink Guard is a small model that finds personal information and credentials in Chinese, English and mixed Chinese and English text. It also works on source code, configuration files, logs, and the API requests that AI coding assistants such as Claude Code, Codex and Cursor send to language models. It runs locally with ONNX Runtime on the CPU, or on a GPU with the FP16 build. It returns each detected span with its label and score, and your application decides what to mask.
AstrLink uses this model for privacy detection.
This repository holds version 0.1.3 in three formats: `int8/` (dynamic INT8, recommended on CPU), `fp32/` (FP32, the higher-accuracy reference) and `fp16/` (FP16 with a fixed 512-token input, for GPU runtimes).

## What's new in 0.1.3
- A new `fp16/` folder holds the 0.1.2 model converted to FP16, for GPU runtimes. Its input is fixed at 1 × 512 tokens (see FP16 build).
- An upcoming AstrLink release adds the FP16 build to its built-in model catalog: Core ML on Macs with Apple silicon and macOS 26 or later, and DirectML on Windows (in testing).
- On the benchmarks in this card, FP16 scores within 0.03 F1 points of FP32. General text F1 is 97.35, code F1 93.83 and coding-assistant macro F1 90.84, the same as FP32.
- `int8/` and `fp32/` hold the same files as in 0.1.2, so INT8 and FP32 results are the same as in 0.1.2. The tokenizer, labels, decoding rules and recommended minimum span score are also the same.
## What's new in 0.1.2
> **Behavior change: `private_date` now covers only dates about a specific person.** The model still flags birth dates, dates on ID cards, passports and other documents, medical and other appointments, and personal travel dates. It no longer flags dates in logs, code and configuration, file listings, HTTP and git headers, record timestamps (`created_at`, `updated_at`, …), release and build dates, or system prompts. If your integration expects every date to be masked, stay on 0.1.1 (`revision="v0.1.1"`) or add your own date rule.
- The model flags far fewer non-personal dates. Of 7,743 non-personal dates in coding-assistant requests, INT8 now flags 21, down from 7,435, and FP32 flags 22, down from 7,439. A separate set of 2,815 non-personal dates comes from logs, file listings, git output, headers, record timestamps, release notes, code, system prompts and work events. On that set, INT8 flags 106, down from 2,786, and FP32 flags 112, down from 2,802.
- The trade-off is that the model now misses some personal dates. Of 1,760 personal dates, 0.1.2 finds 81.5% with INT8 and 82.7% with FP32. 0.1.1, which flagged nearly every date, found 98.6% with INT8 and 98.8% with FP32. The model finds birth dates and travel dates most often and misses dates on documents and medical appointments most often (see Dates).
- The model misses fewer credentials entirely. Of 2,158 credentials in coding-assistant requests, INT8 leaves 51 with no part masked, down from 228, and FP32 leaves 45, down from 159. For the 91 AWS access key IDs (`AKIA…`), the count falls from 8 to 1 with INT8 and from 5 to 1 with FP32.
- There are fewer false positives in coding-assistant requests. Of 187 requests with no personal data or credentials, 20 still get a flagged span with INT8, down from 24, and 24 with FP32, down from 31 (dates not counted).
